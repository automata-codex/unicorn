# M2.5 Implementation Plan — Design Sprint & Base Component Set

**Spec:** `docs/specs/zoltar/m2.5-design-sprint.md`
**Created:** 2026-04-13

Pause after each phase for manual code review and git commit.

---

## Current State

- `apps/zoltar-fe/src/themes/base.css` and `mothership.css` already exist
- `index.html` already has `data-theme="mothership"` on `<html>`
- Theme CSS files are **not yet imported** in the app entry point
- No components exist under `src/lib/components/`
- No `typography.css` exists under `src/lib/styles/`
- App uses Vite + `main.ts` entry (not SvelteKit routing); pages live in `src/pages/`

---

## Phase 1 — Token Loading & Typography

Wire the existing theme CSS files into the app and add the typography utility classes.

1. Import `base.css` and `mothership.css` (in that order) in `main.ts`
2. Create `apps/zoltar-fe/src/lib/styles/typography.css` with the seven utility classes from the spec
3. Import `typography.css` in `main.ts` after the theme imports

**Verification:** `npm run dev` in `zoltar-fe` — page loads without console errors, `document.documentElement` has `data-theme="mothership"`, inspecting any element shows CSS custom properties from both token files are resolved.

---

## Phase 2 — SectionLabel & Card

The two simplest structural components. Card depends on SectionLabel for its primary usage pattern, and both are dependencies of the dev preview page layout.

1. Create `apps/zoltar-fe/src/lib/components/SectionLabel.svelte` per spec
2. Create `apps/zoltar-fe/src/lib/components/Card.svelte` per spec

**Verification:** Temporarily render a `<Card><SectionLabel>TEST</SectionLabel></Card>` in `App.svelte` to confirm tokens resolve and layout looks correct. Remove before committing.

---

## Phase 3 — Button

1. Create `apps/zoltar-fe/src/lib/components/Button.svelte` per spec
2. Implement `primary` and `ghost` variants, `disabled` state, `fullWidth` prop

**Verification:** Temporarily render all button states in `App.svelte`. Confirm hover/active states, disabled styling, and fullWidth behavior.

---

## Phase 4 — Input & Select

These share visual styling, so they belong together.

1. Create `apps/zoltar-fe/src/lib/components/Input.svelte` per spec (label, hint, disabled, focus border)
2. Create `apps/zoltar-fe/src/lib/components/Select.svelte` per spec (native `<select>`, custom chevron, visually identical to Input)

**Verification:** Temporarily render both components with various prop combinations. Confirm focus border, placeholder color, label/hint rendering, disabled state, and chevron visibility.

---

## Phase 5 — ResourceBar & StatusDot

The two data-display components.

1. Create `apps/zoltar-fe/src/lib/components/ResourceBar.svelte` per spec (HP/Stress fill, clamped width, label + value)
2. Create `apps/zoltar-fe/src/lib/components/StatusDot.svelte` per spec (6x6 circle, online/offline)

**Verification:** Temporarily render ResourceBar at various fill levels and both StatusDot states. Confirm fill colors, clamping, and dot sizing.

---

## Phase 6 — Dev Preview Page

Assemble the Storybook-style page that renders every component in every state.

1. Create `apps/zoltar-fe/src/pages/DevComponents.svelte` showing all components and states listed in the spec
2. Add a `/dev/components` route in `App.svelte`'s router logic (dev-only, not in production nav)

**Verification:** Navigate to `/dev/components`. All components render against `--color-bg`. All variants and states visible. Page is usable at 375px viewport width.
