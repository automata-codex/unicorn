# M7.6 — Reconciled Diff

PSG target against the schema as it actually stands. This is the direct input to the spec.

**Sources.** Rules side: `m7.6-psg-character-sheet-inventory.md`, citing *Mothership
Player's Survival Guide* v1.2 by section. Code side: `docs/plans/m7.6-code-inventory.md`
at commit `e1cdaac`. Placement: `decisions.md § State placement is decided by the lifetime
of the referent, not the lifetime of the value`.

**Dispositions.** `KEEP` · `DROP` (no referent in the rules) · `RESHAPE` (right concept,
wrong type) · `MOVE` (right value, wrong container within the sheet) · `→STATE` (leaves the
sheet under the placement rule) · `ADD` (rules concept with no representation at all).

**Counts.** 20 leaf fields exist. 5 survive unchanged. 4 are dropped outright. 11 are
reshaped, moved, or relocated. 14 rules concepts have no representation and would need
adding. **The schema is closer to a rewrite than an edit**, which is worth knowing before
the spec is sized.

---

## 0. A defect in the recorded placement rule, found by applying it

`decisions.md` **lines 471–476**, the bullets under "**The rule.**" in
`### State placement is decided by the lifetime of the referent, not the lifetime of the
value` (heading at 461). The rule mixes two axes across three bullets:

> - The referent never changes after creation → character sheet
> - The referent outlives the adventure → campaign state
> - The referent is created and destroyed with the adventure → adventure state

The first bullet says *referent* and means *value*. A character's Strength and a
character's name have the same referent — the character — so the first two bullets both
match every character field and the rule can't discriminate. It reads fine until you try
to apply it field by field. The lead-in at 471 has the same problem: "State lives at the
scope of the thing it is *about*" describes only the second axis.

**Replacement for 471–476:**

> **The rule**, two axes applied in order:
>
> 1. **Does the value change during play?** No → **character sheet**. Name, pronouns, class, the creation rolls as rolled.
> 2. **For values that do change, how long does the thing they describe last?** Outlives the adventure → **campaign state** (anything attached to a character, a recurring NPC, or the party's ship). Created and destroyed with the adventure → **adventure state** (a derelict's reactor integrity, a synthesized threat's HP, a countdown timer, initiative order, scenario flags).

The entry title survives unchanged — referent lifetime is still what the entry is *for*,
it just isn't the only axis. The worked examples and the Mothership and 5e conclusions are
unaffected.

**The consequence is larger than it looked when we recorded it.** Under the corrected
rule, the sheet retains only immutable creation data — 6 fields. Everything numeric leaves.
That is shape (a) from the inventory's Open Question 1, which was marked resolved on the
narrower claim that *newly added* fields land on the campaign side. Confirm this is
intended before the spec assumes it; §6 lists the alternative.

| Field | Why |

| `level: z.number().int().min(1).max(10).default(1)` | Mothership has no levels. Advancement is Skill Training (§24.1) and Shore Leave (§39.1). Written by nothing, read by nothing — the frontend type omits it entirely |

Dropping `stats.instinct` is not free: `formatMothershipCharacterProse` renders it as
`INST`, so the synthesis prompt currently tells Claude the character has a stat that
doesn't exist. `CharacterView.svelte` iterates `Object.entries(stats)`, so it disappears
from the UI automatically.

## 4. →STATE — leaves the sheet under the placement rule (7 + 2 ceilings)

All seven Stats and Saves mutate in play, so under the corrected rule none of them is
sheet data. Each needs a **current** value in state and a **ceiling** that restore effects
clamp against — and the ceiling is itself mutable, so it can't be recomputed from the
creation roll.

| Value | Moves because | Ceiling needed because |
|---|---|---|
| Strength | Wounds `-1d10` (Fire 04, Gore 04); radiation L2; Stress overflow >20 | Pseudoflesh restores 2d10 |
| Speed | Same | Pseudoflesh restores 2d10 |
| Intellect | Radiation L2; Stress overflow | Psychosurgery restores **to maximum** |
| Combat | Radiation L2; Stress overflow; Military Training `+10` | Slicksim restores 1d10 — **no restore-to-max exists anywhere** |
| Sanity Save | Radiation L2; Stress overflow; Slicksim mishap `-1d5` | Counselor restores 1; Psychosurgery to max; **Shore Leave raises the ceiling** |
| Fear Save | As Sanity | Slicksim restores 1d10; Shore Leave raises the ceiling |
| Body Save | Wounds `-2d10` (Fire 05, Fire 06); radiation L2 | Pseudoflesh restores 2d10 |

| Ceiling | Current field | Change |
|---|---|---|
| Maximum Health | `maxHp` | →STATE. Mutable: Death table `00` takes `1d5` (§29.2). No recovery path exists |
| Maximum Wounds | *(absent — see §7)* | →STATE. Mutable: Panic `19` takes 1 (p. 21). No recovery path exists |

**Container: `resourcePools`. Decided 2026-08-14.** Consistent with
`§ HP and all numeric resources in resourcePools`. Thresholds stay empty for all nine —
none of these values fires a mechanical event on crossing a number, so the threshold
machinery is simply unused rather than worked around.

**The per-instance `max` is already the right home for the mutable ceilings.**
`ResourcePoolSchema` is `{ current, max }` per pool, distinct from `PoolDefinition`'s
system-level `min`/`max`/`thresholds`. So a stat pool is `{ current: 27, max: 42 }`,
Maximum Health is the hp pool's `max`, Maximum Wounds is the wounds pool's `max`. No
separate ceiling pools, and the mutability comes free.

**But nothing can write `max`.** `state_changes.resource_pools` is
`Record<string, { delta: number }>`. Death-table `00` reducing Maximum Health by `1d5`
(§29.2) and Panic `19` reducing Maximum Wounds by 1 (p. 21) have **no write path at all**.
Choosing pools as the container therefore forces a tool-schema change — and it is the
*same* schema change as Open Question 5's delta provenance. Both alter the pool-delta
object, both need matching Warden prompt instructions, both need this milestone's
re-baseline. Two open questions collapse into one decision about what that object should
carry.

**Below-`min` deltas stay rejected rather than clamped. Decided 2026-08-14** — the Warden
sets these values and should apply the floor itself. Two places where that is not a
philosophical choice but the only option available, worth recording as such so they don't
read as consistent with the general policy:

- **Stress cannot get its correct floor from the mechanism.** `PoolDefinition.min` is a
  system constant selected by string suffix. Mothership's floor is *Minimum Stress*, which
  is per-character and mutable (§20.2). The definition mechanism cannot express it.
- **Nor its cap.** §20.1 does not reject overflow past 20; it converts the excess into a
  reduction of the most relevant Stat or Save — a cross-pool effect no validator supports.
  `max: null` plus a prompt instruction is the only available shape.

**One empirical caveat.** A rejection triggers the correction loop, bounded at one
re-prompt, so a persistent Warden mistake fails the turn. Going from two rejecting pools to
ten widens that surface. "Should be smart enough" is the same class of assumption as
`SYSTEM-ROLLED-PLAYER-ACTION`, which sat at 0.45 until the prompt was fixed and measured.
Cheap insurance: count rejections per pool in telemetry during the re-baseline, so the
assumption is measured rather than trusted.

**Remaining work the container choice implies.** `getMothershipPoolDefinition` selects by
string suffix (`*_hp`, `*_stress`, else default). Ten pools means either ten suffixes or a
different selector.

## 5. RESHAPE — right concept, wrong type (4)

| Field | Current | Target | Why |
|---|---|---|---|
| `maxStress` | `z.number().int().min(1)` | **`minimumStress`**, →STATE | There is no per-character maximum Stress. 20 is a system constant (§20.1). The per-character value is *Minimum* Stress: starts at 2, raised by Panic 04/14/18/19 and "Awesome scar", lowered by Nanogel, reset to 2 by Psychosurgery |
| `skills` | `z.array(z.string())` | `{ skill, tier }[]` over a fixed prerequisite graph, with per-skill suppression | Tiers are +10/+15/+20 (§22–23) and drive the bonus. Prerequisites are directed edges (§24.1). Panic `08` suppresses one skill's bonus for the life of a Condition — a link between a Conditions entry and a Skills entry |
| `equipment` | `z.array(z.string())` | stateful items with counts | Loadouts carry charges, rounds, and doses: "Revolver (12 rounds)", "Stimpak (x5)", "Patch Kit (x3)" (p. 7). Stimpak use is dose-tracked over 24 hours with an overdose Death Save (§33.3) |
| `saves.armor` / `armorMax` | two integers | worn-armor object, →STATE | AP is consumed: damage ≥ AP **destroys** the armor (§28.3); a patched vaccsuit is AP 1. Plus DR applied first and surviving destruction, an O2 clock, a Speed penalty when Heavy, and integrated features (radiation shielding, air filter, exoskeletal weave `[+]` to Strength Checks) |

## 6. Sheet contents after the diff

| Stays | Leaves |
|---|---|
| `entityId`, `name`, `pronouns`, `class`, `notes`, plus `trinket` and `patch` from §7 | Everything numeric, every mutable list |

Optionally also the **creation rolls as rolled** — an immutable record of what was rolled
at creation, distinct from the current values and from the mutable ceilings. Useful for
audit and character-history display; not read by any mechanic.

**The alternative, if a near-empty sheet is unacceptable:** shape (c) — the sheet keeps
creation rolls *and* mirrors current values, with state authoritative. That was rejected
implicitly by the placement rule's own rationale ("drifted from the authoritative pool
values the moment play began"), and the code inventory shows the drift already happening:
`mergePlayerResourcePools` cannot overwrite, so raising `maxHp` on a sheet today never
reaches the pool. Recording the alternative because the near-empty sheet is a bigger
change than the milestone note anticipates, not because I think it's right.

## 7. ADD — rules concepts with no representation (14)

| Concept | Rule | Placement |
|---|---|---|
| **Wounds, current** | §28.2 — Health at zero gives a Wound and a Wounds Table roll | →STATE |
| **Wounds, maximum** | 2, +1 Marine, +1 Android; Panic `19` takes 1 | →STATE |
| **Stat/Save ceilings ×7** | Restore effects clamp against them; Shore Leave raises Saves | →STATE |
| **Conditions** | Panic 05–10, 12, 17; parameterised (*Frightened* stores what; *Loss of Confidence* stores which skill) | →STATE |
| **Trauma Response** | Class-derived *except* Military Training grants the Marine's to any class (§25.1) — a stored field, not a derivation | Sheet or state, depending on §6 |
| **Skill Training** | `{ skill, monthsRemaining }`, at most one; on the printed sheet as a first-class slot | →STATE |
| **Credits** | 2d10×10, or 2d10×100 if forgoing a loadout (§6.1) | →STATE |
| **High Score** | Sessions survived (§18.3). No mechanical effect by default | →STATE |
| **Trinket** | d100 (p. 8) | Sheet (immutable) |
| **Patch** | d100 (p. 9) | Sheet (immutable) |
| **Worn armor** | See §5 | →STATE |
| **Bleeding** | §32.2 — cumulative per-round damage, `+1` to `+7` from the Wounds table, ignores armor and DR | →STATE |
| **Pending Death Save** | Wounds Lethal Injury row — "Death Save in 1d10 rounds", a timer | →STATE |
| **Pets** | Own statblock: Wounds 1(10)/2(15), Instinct, skills; impose Stress on the owner (§11.1) | Probably an entity — Open Question 4 |

**Wounds is the largest single gap and is a mechanic, not a field.** `HP_DEFINITION`'s only
threshold is `{ value: 0, effect: 'death_save_required' }` — the 5e rule. Mothership routes
0 HP into a Wound, a Wounds Table roll by damage type, and a Health reset to Maximum minus
carryover; the Death Save arrives only at Maximum Wounds. `HP_DEFINITION.min` is also
`null`, so HP currently goes negative and stays there instead of triggering the cycle.

The §5.5 states from the PSG inventory — cryosickness, exhaustion, food and water,
radiation level, temporary roll modifiers — are deliberately not listed here. They're
Phase 1 scope questions (Open Question 6), not omissions.

## 8. Defaults and ranges that are wrong independent of shape

| Location | Current | PSG |
|---|---|---|
| `CharacterCreate.svelte:37` | `maxHp = 20` | `1d10+10` → 11–20. A fixed 20 is the maximum roll |
| `CharacterCreate.svelte:38`, `CharacterEdit.svelte:44` | `maxStress = 3` | No referent. Minimum Stress starts at **2** |
| `CharacterEdit.svelte:68-80` | `?? 30` on every stat and save | Stats are `2d10+25` → 27–45 (36 average, §"A Stat of 36 is average"). Saves are `2d10+10` → 12–30 |
| `character-pools.ts:22` | stress seeded `current: 0` | Starts at **2** (§20.1) |
| `STRESS_DEFINITION.min` | `0` | Floors at Minimum Stress, itself mutable, never zero (§20.2) |
| `STRESS_DEFINITION.max` | `null` | Hard cap **20**; overflow reduces the most relevant Stat or Save (§20.1) |
| `stats`/`saves` range | `.min(0).max(100)` | Plausible for Stats. Saves can exceed 100 in principle — Shore Leave raises them without a stated bound |

The class Stat/Save adjustments (§"Step 3") aren't applied anywhere in the creation flow
either — Marine `+10 Combat / +10 Body / +20 Fear / +1 Max Wounds`, Android `+20 Intellect
/ −10 to one Stat / +60 Fear / +1 Max Wounds`, Scientist `+10 Intellect / +5 to one Stat /
+30 Sanity`, Teamster `+5 all Stats / +10 all Saves`. Creation is currently free-entry with
defaults.

## 9. Blast radius, by change

| Change | Reaches |
|---|---|
| Any `stats`/`saves` shape change | `formatMothershipCharacterProse` (renders all six stats and all four saves as prose — **the widest reader**), `CharacterCreate`, `CharacterEdit`, `CharacterView` (auto-adapts via `Object.entries`), `CampaignDetail` |
| `maxHp` / `maxStress` | `deriveMothershipCharacterResourcePools`, `Play.svelte:124-130` (`fallbackMaxHp`/`fallbackMaxStress`), `play-helpers.ts:44-66` |
| Anything numeric moving →STATE | `MothershipCampaignStateSchema` → **every fixture's `campaignState`** → `FIXTURE_SCHEMA_VERSION` bump. This is the actual corpus coupling; the sheet has none |
| Pool definitions | `getMothershipPoolDefinition` selects by string suffix (`*_hp`, `*_stress`, else default). Ten pools (seven stats/saves, hp, stress, wounds) means either ten suffixes or a different selector |
| Any read-side validation | **Breaks every eval run.** `harness-runner.ts:326` seeds 1 of 9 required fields deliberately, and it works only because no read path parses the sheet |
| Ceiling changes on the sheet | Do **not** reach the pools. `mergePlayerResourcePools` cannot overwrite; the migration must write both |
| Nothing | `apps/zoltar-fe/src/lib/types.ts` — hand-written, `Record<string, number>`, not imported from `@uv/game-systems`. It won't catch any of this at compile time |

## 10. Decisions this diff forces, in order

1. **Confirm or amend the placement rule's first bullet** (§0), and confirm the near-empty
   sheet is intended (§6). Everything below depends on it.
2. ~~**Container for the relocated values.**~~ **Resolved** — `resourcePools`, thresholds
   empty, per-instance `max` carrying the ceilings, below-`min` deltas rejected (§4).
3. **What the pool-delta object carries.** Forced by #2: ceilings need a write path that
   `{ delta: number }` doesn't provide, and Open Question 5's delta provenance touches the
   same object. One tool-schema change, one set of prompt instructions, one re-baseline —
   decide the full shape once. **This is the only item with a deadline.**
4. **Wounds: in or out of M7.6.** It's the largest gap and it's a mechanic — Wounds Table
   by damage type, Health reset with carryover, Death Save at maximum. Deferring it is
   defensible; deferring it *silently* is how it got here.
5. **Conditions placement and shape** — Open Question 3, unchanged.
6. **How much of §7's tail is Phase 1** — Bleeding is common enough in play to be
   load-bearing; pets, Skill Training, and Credits plausibly aren't.
7. **Rejection telemetry per pool** at the re-baseline (§4) — cheap, and it converts the
   "the Warden will apply the floor" assumption into a measurement.
